# 일반 구좌 최근 반복 방지

`mcp_operations.direct_snapshot`의 `rotation_policy`는 같은 CMS 관리자 소유의 완료된 MCP 일반 구좌 영수증만 읽는다. 슬롯별 `after.product_ids - before.product_ids`로 실제 새 편성 작품을 계산하고 한국시간 편성 날짜부터 7일 동안 재추가 제한 대상으로 제공한다. 10월 6일 추가한 작품은 10월 13일부터 다시 추가할 수 있다.

`recently_added`에는 실제 추가 날짜와 다시 가능한 날짜가 포함된다. `avoid_reproposal_product_ids`에서는 현재 어느 일반 구좌에든 유지 중인 작품을 제외한다. 그대로 유지하거나 현재 편성 작품의 위치를 바꾸는 것은 신규 재추가로 취급하지 않는다. 신규 작품이나 오래된 작품이라는 이유만으로 우선하지 않는다.

`apply_direct`는 CMS 행 잠금 및 최신 상태 비교 이후, 쓰기 의도를 저장하기 직전에 같은 이력을 다시 읽는다. 현재 일반 구좌 전체에 없는 작품을 새로 추가할 때만 최근 7일 재추가를 거절한다. 빈 업데이트의 유지 결정과 기존 완료 영수증 반환은 보존한다. 영수증 형식 또는 슬롯 메타데이터가 손상되면 CMS 변경 전에 오류를 반환한다.

조회는 소유자·완료 상태·7일 날짜 범위로 제한되며 정상 이력은 최대 7건이다. OAuth·토큰·다른 관리자·실패 및 진행 중 영수증을 읽지 않는다. 과거 로컬 제안 기록은 가져오지 않았으며 `legacy_local_proposal_history`에 `unknown`으로 명시한다. 실제 실행 영수증 기반 제한이므로 미실행 제안까지 추적하는 기능은 아니다.

닷의 편집 판단은 조회수나 반응이 적다는 이유로 기회를 좁히지 않고, 최근 편성 중복을 피하며 적합한 작품에 고르게 기회를 주도록 설정한다. 이 서버 검증은 미편성 제안 기록이나 구좌 간 동시 중복까지 해결하는 무작위 선정기는 아니다. 무료 신작의 최신순·정원, 명시적 유지 작품 등 기존 구좌 제약은 계속 적용한다.

테스트는 임시 SQLite 영수증과 mock CMS 세션으로 경계 날짜, 현재 유지, 소유자 분리, 인증 기록 미접근, 손상 기록 차단, 조회 메타데이터 및 적용 직전 재검증을 확인한다. 실제 CMS·DB 변경, 배포 또는 Gemini 생성은 하지 않는다.
