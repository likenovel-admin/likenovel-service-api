# 단일구좌 기회 우선 순환

`fastapi_be_server/app/services/ai/mcp_single_copy.py:rank_candidates`가 조회수·북마크·유료전환 날짜·작품 ID를 순위 기준으로 사용하지 않는다.

1. 실제 단일구좌 이력이 없고 제안 이력도 없는 작품을 먼저 둔다.
2. 그다음 실제 노출 이력 `last_single_slot_at`과 보존된 `state.last_proposed_at` 중 최근 날짜가 오래된 작품을 먼저 둔다.
3. 같은 한국시간 날짜의 기회 이력끼리는 `random.shuffle` 후 안정 정렬로 무작위 순서를 유지한다. 같은 실행의 초·분 차이로 순환이 고정되지 않는다.

`mcp_operations._generate_single_inner`는 기존 rotation receipt를 읽고, 최초에는 기존 운영 이력을 가져온다. 이번 변경은 해당 이력 저장·적용 흐름을 바꾸지 않는다. 제안이 최근 있었으면 실제 노출을 받지 않았더라도 기회를 받은 것으로 취급한다. 현재 활성 단일구좌 작품은 기존 `CANDIDATE_SQL`의 `NOT EXISTS`로 제외된다.

기존 SQL의 유료·전체이용가·연재중·공개 회차·표지·시놉시스 조건, 중복 ID 거부, 표지 검사, 정확히 3편 선택, Gemini 문구 원문 근거 검증, 월·목 주기, 적용 직전 재검증은 그대로다. SQL의 결과 정렬에는 조회수 항목이 남아 있지만 제한 없이 받은 후보를 이 순위 함수에서 다시 섞어 정렬하므로 최종 순위에는 영향을 주지 않는다.

범위는 유료 단일구좌 후보 순위다. 일반 5개 구좌의 판단 및 제안 알림 정책, AI독자·회원메일·프로모션·유료전환 실행 권한은 바꾸지 않는다. 무작위는 암호학적 추첨이나 모든 작품의 노출 보장이 아니며 표지·작품 조건 불합격은 계속 제외한다. 실제 생성·CMS 변경·배포 없이 순위 및 표지 선택만 mock 검증한다.
